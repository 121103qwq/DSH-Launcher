# 架构决策记录（ADR）

> 目的：把"为什么这么做"固化成可引用的条目，避免后来的改动推翻既有约束而不自知。
> 体例：背景（为什么会有这个决定）→ 决策 → 后果（constrains / enables）。
> 来源：`work-log/*`、`lessons/*` 的既有结论；每条都指向可核对的证据，不写没发生过的事。

---

## ADR-001 · 测试与验证不得触碰真实数据

- **背景**：早期 harness 会写用户的真实 `launcher.log` 与数据根，验证动作污染真实状态（work-log/46 P2-5）。
- **决策**：
  1. 日志类测试用 `DSH_LAUNCHER_LOG_ROOT` 隔离；
  2. 数据类测试一律用临时数据根（`LauncherPaths(临时目录)`）；
  3. UI 冒烟中凡"点击即写盘/删盘"的控件**只断言存在、不点击**；
  4. 需要写真实数据的验收（如 A3 卫生复位）**先问用户并先快照**。
- **后果**：验证可反复运行；代价是部分路径只能人工验收（已在行为矩阵中标注）。

## ADR-002 · 凭据：只看位置，不看值

- **背景**：安全体检要能回答"哪里有密钥"，但任何把值带进日志/导出物的实现都是新的泄露面。
- **决策**：
  1. 默认只输出**文件 / 行 / 列 / 模式名**；值不进入任何 DTO 字段；
  2. 脱敏预览必须**显式开启**，且只保留前 3 + 后 4（中段一律 `•`）；
  3. 第三方探针写入的 `raw`（原文）**永不读取**；`key`（片段）仅在显式开启预览时读取；
  4. 安全类改动必须配**安全反证**（见 ADR-003）。
- **后果**：体检结果可以放心展示/导出；代价是无法在 UI 内做"密钥可用性校验"这类功能（明确不做）。

## ADR-003 · 安全功能必须配安全反证 + 双向自校准

- **背景**：安全功能"报得少"与"没生效"在现象上无法区分；一次假通过会让后续所有结论失效。
- **决策**：
  1. 每个安全相关能力都要写出"**证明它不会泄漏/不会写盘**"的断言（如报告序列化不含凭据值及中段特征、体检前后临时 HOME 零变化、日志零泄露、UI 文本层零泄露）；
  2. 断言必须**双向自校准**：危险样本必须全部命中，安全样本必须零命中；
  3. 断言"没泄露"之前，必须先断言"确实渲染/命中了"（否则会因"什么都没做"而假通过）。
- **后果**：SelfTest 中安全相关断言数量显著增加；换来的是结论可信。

## ADR-004 · 体检类功能直接读文件，不调用 dsh CLI

- **背景**：`dsh --profile web --dump-config` 看似"只打印配置"，但在空 HOME 里实测**会生成 profile 脚手架**（写盘）。
- **决策**：安全体检 / 危险配置检查一律**直接读文件**（profile 层 `cordis.yml`/`cordis.patch.yml` + `$DSH_HOME/settings.yaml` + 运行时出厂层）；读不出的 `!!js` 表达式**记 Notes 不猜**。
- **后果**：保持了"纯读取"的反证；代价是自造解析（仅覆盖高置信度键，见 `DangerousConfigAuditService`）。

## ADR-005 · 整合包导入永远新建实例，失败整体回滚

- **背景**：导入是"把别人的配置装机"，最不能接受的是**覆盖用户现有实例**或留半成品。
- **决策**：
  1. 一律新建实例（HOME 固定在 `instances/<新ID>/dsh-home`）；
  2. `package.json` 由 manifest **权威重建**（不照抄包内文件）；
  3. 运行时**共享模板实例的**（不复制 266 MB）；版本不符时**先提示、再选择**（换模板 / 下载安装 / 取消，work-log/78）；
  4. 任一步失败：注销注册表 + 删 HOME + 删空的 `instances/<ID>`（自测不变量：`instances` 目录数 == 台账实例数）。
- **后果**：导入可反复试错；代价是每次导入都是新实例（用户需自行清理不再需要的实例）。

## ADR-006 · 契约清单 + 哨兵：优先防御"静默失效"

- **背景**：上游改键名/改默认值时，我们的功能**不会报错**，只会安静地什么都查不到——这类失效没有症状。
- **决策**：
  1. `docs/DSH_CONTRACT_INVENTORY.md` 逐条记录依赖点（权威定义 / 落点 / 破坏时症状 / 哨兵）；
  2. 哨兵规则：**能从源码或已安装运行时静态核对的才做**（如读出厂层 `cordis.patch.yml` 断言权限键位与遥测官方域）；上游克隆缺失时整段 SKIP 而不是误报失败。
- **后果**：C1–C19 + harness 348 条断言；代价是上游升级时需要维护哨兵。

## ADR-007 · 来源管理：唯一固定来源 + 可开关的预置条目

- **背景**：中文源接入后，来源列表出现"内置/自定义"两套语义，用户无法统一开关与测试。
- **决策**：唯一固定来源 = GitHub（awesome 目录 + GitHub 搜索）；中文源（deepseek1024 / dshfind）降为**自定义列表里的预置条目**（可用适配器令牌 `adapter:*` 开关/测试/删除，默认停用）；Skill 来源保持原状。
- **后果**：来源页语义统一；代价是换机器时预置条目需重新启用（首次会预置，删除后不再自动回来）。

## ADR-008 · 运行时行为不许用推断代替数据

- **背景**：实例：市场"拉到底不追加"，我据"窗口滑动到底"**推断**为"外层滚动器在滚"，据此改了代码；用户澄清滚动的就是列表 → 推断被推翻（work-log/79）。
- **决策**：涉及运行时行为的判断，必须先取数据（日志一行 / 运行时数值 / 探针），再动手；推断只能作为"待验证假设"写进台账。
- **后果**：定案慢一步，但避免改错方向与污染代码；这条同时适用于"验证方法必须先自校准"。

## ADR-009 · 上游代码只借鉴思路，不复制

- **背景**：参考的同类启动器仓库许可情况不一（其中包含明确 MIT 的项目，也有未声明许可的）。
- **决策**：只借鉴**思路与数据结构**，不复制代码；需要参考具体实现时，仅阅读并重写（如 `@marcog-h/dsh-audit` 为 MIT，用于核对字段语义，未复制代码）。
- **后果**：发布/公开分发时许可风险可控；代价是实现工作量略高。

## ADR-010 · 发布 SOP 固定为"停 → 建 → 测 → 发 → 核 → 起"

- **背景**：Launcher 运行中执行 `dotnet publish` 会出现 MSB4018（文件占用）。
- **决策**：发布必须按顺序：**停 Launcher** → `dotnet build`（0 警告 0 错误）→ SelfTest → `dotnet publish` → 复制到安装目录 → **MD5 核对 dist 与安装副本一致** → 重启 Launcher；harness 也应在停 Launcher 后运行（避免日志/端口干扰）。
- **后果**：发布可重复、可核对；代价是每次发布多几步（已固化为脚本化命令）。
